# 精选与校准

## 本站收录范围

本站保留 AI 教学与教育信息化政策规范主线，同时收录通用 AI 实践、演示与玩法。通用实践不必先证明教师用途，不要求出现“职教”、已有课堂案例、新发布、成功完成、源码或完整复现步骤。

判断依据是：能辨认用什么 AI、做什么任务，并提供具体方法、实际结果、能力演示或使用经验中的至少一项。包括：

- 图像、音视频、动画、SVG、网页、游戏与 3D 创作，风格控制和交互玩法。
- 提示词、上下文与多轮交互技巧，智能体、Skills、MCP、知识库、自动化与办公工作流。
- AI 编程、数据分析、硬件与多模态应用，工具实测、费用／速度／效果对比、失败复盘与排错。
- 模型部署、API 接入、推理服务、GPU 推理配置与优化的具体方法、条件或经验。

沿用现有“教程”分类（`tip`／`教程/实践`）：有操作过程、提示词或工作流的是教程／实践；只有任务与结果的是演示／玩法案例，摘要不能将其包装成完整可复现教程。官方展示可收录，但只说明官方展示的内容，不冒充独立验证、所有用户可用或教学效果。无教学关联的通用实践不强行标为“AI 赋能教学”；工具目录仍归“AI 工具”。

仅有名称、购买入口、榜单或“效果惊艳”“模型最强”等口号，没有具体任务与实质信息的宣传仍拦截；材料确实不足以辨认范围时 `UNKNOWN`，继续按 `BLOCK` 处理。模型调用成功不等于内容通过。收录与精选分开：范围内、分析通过的低分演示可以进入“全部动态”，精选仍按原有五轴、权重、门槛与去重规则决定，数值不因扩展范围而降低。

2026-11-06 扩展的是预筛、分类、评分和写作的共同范围。历史 UNKNOWN／BLOCK 不因提示词更新自动改成 PASS；新提示词不能反过来证明旧模型已经通过。使用者随后确认新增 UNKNOWN 专用人工预筛审核和以下六个指定来源的预筛直通策略；其他来源的 BLOCK 仍须重新评估。真实模型是否准确执行新范围，需要用使用者确认的样本评测，不能用本地假模型测试代替。

2026-11-06 使用者再确认 `catalog-uisdc-nav`（优设 · AI 导航，<https://hao.uisdc.com/ai/>）走同一套**目录直接公开**：单页 20 个分类块（热门推荐、Agent 智能体、AI 绘画……探索更多）解析出 288 条唯一资源，只收目录已有的名称、简介、标签和图标，不抓目标站正文、不请求模型，费用 0。身份是目标地址的归一化形式，同一资源出现在多个分类时只留第一条及其分类标签；无发布日期的目录条目按首次发现时间入「全部动态」，不自动入精选或事件。后台新增的 `ai_list`（AI 抽取列表）信源类型**不在**这个名单里，它只负责抽取列表，发布仍走正常的预筛、评分和写作。

来源放行与模型判断分开记录：新分析保存来源策略 PASS 和绑定来源 ID、当前材料版本的 `sourcePrefilter`，历史原始 UNKNOWN／BLOCK 与收费回执保持原样。新旧资料继续评分、结构分类与通用模型写作；材料不足、分析失败、写作无效、拦截标签和人工下架仍不可公开，精选门槛不变。公开层复核来源证据，不能用旧版本或其他来源的放行记录公开。历史重入队命令见 [部署更新](deploy.md#更新)，不会删除资料或重新全量抓取。

### UNKNOWN 人工预筛审核

后台“内容诊断”选择预筛 `UNKNOWN` 并查找，可逐条勾选、选择当前页或“选择全部匹配”（包含其他页），点击“人工判为 PASS”。详情页也提供同一入口。预览显示确切范围、可审核数和跳过理由，填入原文核验理由后确认。每批最多 1000 条，超限请用关键词分批。这里的 UNKNOWN 是当前版本的原始预筛标签，不是预筛已经 PASS、却因材料或写作不足产生的最终 `unknown`。

人工审核只通过预筛，不直接公开或强制精选，不修改原始 UNKNOWN、回执、预算和人工下架。worker 复用原始预筛证据，继续原有评分、结构分析和写作；后续分析通过且无拦截，统一发布层才自动公开。缺少有效写作、命中拦截标签、模型失败或材料版本变化仍不可公开。材料更新后人工授权失效，需要对新版本重新核验。

提交使用绑定管理员的版本快照，不会顺带审核预览之后新增的 UNKNOWN。已变化、已审核、等待处理或正在处理的条目跳过；逐项保存授权、后续任务和审计，失败项回滚。结果返回实际已排队、跳过和失败数量及原因，重复提交同一请求不会重复入队。历史 UNKNOWN 默认仍拦截，更新功能不会自动审核它们。

## 一条资料怎么变成精选

1. **收进来**：同一网址、同一内容只留一份。普通文章只有标题或摘要时，按信源规则补取正文；视频播放页使用已提供的文字材料，不把播放器页面当正文。没有可信发布时间时保留首次收录时间，公开信息流标注“收录”，重抓不刷新日期。PDF 政策公告只保留文件名称和原文／PDF 链接，不解析 PDF 正文。
2. **预筛**（`prefilter.md`）：是否属于上述教学／政策主线或通用 AI 实践、演示与玩法范围，不先判断精选价值。有效预筛 `PASS` 继续评分、结构分析和写作；六个指定来源按来源策略直通。其他来源未经专用人工审核的 `UNKNOWN` 与 `BLOCK` 都归一化为 `block`，不公开。人工审核的 UNKNOWN 保留原始判断，另记有效预筛 PASS，后续分析仍须通过。只有标题、没有正文、订阅摘要或帖子文字的普通文章先等待材料；已识别的 PDF 公告例外，仅按名称预筛和分类，预筛通过时展示名称与链接，不评分、不写摘要。编辑信源当前版本的成功通过分析自动公开，待分析、失败、过期分析、被拦截和人工下架保持不可见。公开不等于精选，精选继续遵守原有评分、文案与日期条件。可展示的空文字或纯链接原帖只有预筛通过后才沿用评分与原样展示规则。
3. **评分**（`selection-score.md`）：同一份评分标准独立打两次分（0–100）。**两次之和 ≥ 2 × 门槛**就够分，门槛按信源分级不同；够分的还要过第 6 步的去重才进精选。页面上显示的分数是两次的平均（向下取整）。
4. **结构化**（`structure.md`）：和评分同时进行。给出分类和标签（页面上显示的就是这一份）、主体公司，判断这篇是一条具体新闻、讲多件事的综合稿，还是材料不够、说不清；是具体新闻的，抽出它的事实（谁、做了什么、对什么、什么时候）和原文里的出处、前提条件。主题页、事件归组和日报都靠它。
5. **写标题摘要**：等结构化完成再写。入选的和差一点入选的（平均分高于 `understandFloor`），按 `content-understanding.md` 写中文标题、答案先行的摘要和推荐理由；其余的按 `summarize-*.md` 写简短的标题摘要，进“全部动态”。X 帖子没有正文或只含链接时，保留原帖的链接、图片和引用，不调用写作或翻译模型，也不生成“请补充正文”的文案；已经取得实际正文的 X 长文照常处理。写好的文字用了 `industry/wording.ts` 里列出的词时，再让模型只改这些词一次（`mend-wording.md`）。
6. **归组与去重**（`group-*.md`）：不同来源报道的同一件事归成一个事件，事件页有综述（`story-digest.md`），“热门”按事件排。修改综述提示词前，可用 [综述评测](story-digest-evaluation.md) 在同一批事件上把现有提示词和候选提示词并排比较。分数够了的资料要等归组完成才进精选：模型同时判断它和精选里已有的报道是不是同一条新闻，以及它有没有精选还没给过的具体信息。
   - 同一条新闻的几篇报道都可以入选：网页上折成一个阅读组；API、RSS 和同步接口每条新闻只出一条，由代表报道出面：官方一手优先；其次是核实过的官方账号（填了 `publisherRole` 和 `owner_entity_id` 的 `T1_5` 账号，新闻的主体正是这家公司，机构先于个人）；再往后是有全文的、分数高的、发得早的。
   - 不是同一条新闻、但没有新信息的（换个说法再介绍一遍已经披露的能力、只是上架到别的平台、只重复已选要点的汇总），不进精选，留在“全部动态”。讲多件事的综合稿不单独成事件，只挂到它提到的事件上，有精选没覆盖的重要内容才入选；材料不够、确认不了是哪条新闻的，不进精选。
   - 显式撤回的报道保留历史归属，但不再参与之后的归组召回、候选代表、事件起点或自动事件比较；同网址及 X 回复／引用也不能借它提供身份依据。同一事实仍有有效报道时使用有效稿，全撤回则暂不召回；恢复公开后可重新参与。只展示摘要或尚未发布的记录不等于撤回，保留原有资格。已有关系和判断不删除，不批量重新归组。
   - 确认之前资料只在“全部动态”里，等得再久也不会自动放行。模型调用失败或回答不合格式，这条资料就停在那里：等待超过 10 分钟会告警，后台“运行”页列出这些资料，可以在后台“内容诊断”里打开这条资料，点“重新归组”。所以归组用的模型要能稳定按格式回答。
7. **日报、周报、月报**：
   - **日报**每天 08:00 出（日报、周报、月报的出刊时间在 `site/site.ts` 的 `EDITION_TIMES`，下面按默认值写），覆盖前一天 08:00 到当天 08:00，按规则编排，不调用模型。一件事一条，取报道最多的那条新闻里最权威的一篇，同一事件当天的其他进展列在下面，讲多件事的综合稿挂到它提到的最重要那件事下面。最近 7 期报过的不再出现；报过的事件再有进展，只有当事方自己有新动作（教程、观点这类 `commentary` 类别不算）、或这条进展有 4 家以上信源报道时才进正文，其余进快讯。没有报道入选、但有官方原帖并且已有 3 个以上独立参与方的事件也会补进来（只进日报，不进精选、不推送）。按重要性排序（入选报道的最高分、当天讨论它的独立参与方、有没有官方原帖，跟进的减分），前 12 条进正文，同一信源最多 2 条，再往后最多 10 条一行快讯。第一条是头条，导语就是它自己的标题和摘要；第 2–4 条是今日看点。
   - **周报**（每周一 10:00）和**月报**（每月 1 日 10:30）由这一周、这个月的日报汇编：同一事件跨天只算一件，按日报给它的位置（头条、看点、上了几天）、报道面和评分排序，周报取前 20 件、月报取前 30 件，按日报的分节分栏目。模型（`report-period.md`、`report-period-sections.md`）只写总述和三件以上栏目的一句导读，不增删条目；它写出了条目里没有的名字或数字（拉丁字母的名称、三位以上或带小数点、百分号的数字、词表里的公司），这段话就不用：总述换成按模板生成的一句，栏目不放导读。行业通用词（`taxonomy.ts` 的 `PLAIN_TERMS`）和站名不受这个限制。
   - 每条精选只进一期：按它的时间算，确认入选比它晚的按确认时间；截止以后才确认的进下一期。
   - 每半小时检查一次：到点的刊期出一次，已经出过的不重写；停机错过的、失败的，在之后的检查里补上。日报时段里有资料经过判断、但没有新事件时照常出空刊；没有任何资料经过判断仍算失败，缺期按[部署说明](deploy.md#更新)告警。周报、月报的周期内，应有日报齐全且原始正文条目全部为空时，自动跳过该期，不写空周报或月报、不调用模型，也不记为生成或失败；首个周期从全站最早日报开始检查。没有可汇总条目时，若缺失日报或原有条目后来无法公开，仍保留原有错误。跳过不写永久标记，在现有补刊范围内更正日报后可重新生成。

每一步的提示词都在 `industry/prompts/`，改提示词不用改代码。提示词的版本就是它内容的哈希：改了提示词，之后的新资料按新版判断，已经判过的不会重算。

## 门槛：`industry/selection.ts`

```ts
export const SELECTION = {
  blockedTags: ["其他"],                       // 命中任一拦截标签，直接视为 block
  thresholds: { T1: 60, T1_5: 65, T2: 76 },   // 两次评分的平均至少要到这个数
  understandFloor: 50,                        // 平均分高于它的未入选资料，也按入选的写法写
};
```

官方一手信源（T1）门槛低一些，媒体和个人（T2）门槛高一些：同样一件事，官方原文更值得先看。没有门槛的分级（`EXCLUDE_MP`）不参与精选。

本站把带 `#其他` 标签的内容统一视为 `block`：不论标签排在什么位置、评分多高，均不进入精选、全部动态、详情、RSS、公开 API 或 Markdown。分析时记录为 `block`；发布时还会检查人工修正后的有效标签，手动设为精选或公开不能绕过。原始资料和分析记录保留，供后台诊断。调整拦截标签后，已有内容需重建发布快照才能同步生效，无需重新调用模型。

这组数是 AIHOT 在 AI 领域一直在用的门槛，偏严：宁可少选几条，也不让噪声进精选。换了行业、改了评分标准，一定要按下面的办法重新校准。

## 校准

### 1. 准备样本集

从你自己的信源里挑 100–200 条资料，一条一条标“该选 / 不该选”，存成 `.data/gold.jsonl`（`.data/` 不进 Git）。每行一条：

```json
{"caseId":"law-001","material":{"title":"原文标题","originalTitle":null,"publishedAt":"2026-10-01T09:00:00+08:00","sourceName":"信源名称","bodyZh":null,"bodyOriginal":"正文……"},"sourceFacts":{"sourceKind":"rss","sourceTier":"T1","firstParty":true,"language":"zh"},"samplingContext":{"benchmarkSplit":"development","samplingStratum":"regulation"},"gold":{"decision":"select"}}
```

| 字段 | 说明 |
|---|---|
| `caseId` | 唯一编号 |
| `material` | 标题、原标题、发布时间、信源名、正文（中文正文放 `bodyZh`，原文放 `bodyOriginal`，有一个就行） |
| `sourceFacts` | 信源类型、分级、是否一手（线上只有 `T1` 算一手，标注时保持一致）、语言。分级决定用哪个门槛 |
| `samplingContext` | 可选。`benchmarkSplit` 分开发集和留出集，`samplingStratum` 是你自己的分组（比如“新规”“判决”“营销”），看错在哪一类 |
| `gold.decision` | `select` 该选，`reject` 不该选，`either` 两可（不计入准确率） |

`industry/gold.example.jsonl` 有两条示例。

几条建议：

- 多放**难例**：差一点就该选、差一点就不该选的。一眼就能判断的放太多，准确率会虚高。
- 分出一部分做**留出集**（`benchmarkSplit: "holdout"`），调提示词只看开发集，最后再用留出集检查一遍，免得把提示词调成只会做这几道题。
- 标注的人最好就是以后读这个站的人，或者和他们口味一致的人。
- 评测只跑预筛和两次评分，不含第 6 步的去重：按这条资料本身该不该选来标，不要因为同一件事已经选过另一篇就标“不该选”。

### 2. 跑评测

```bash
node --env-file=.env scripts/eval-selection.ts --gold .data/gold.jsonl --split development
```

对每条样本跑一遍预筛和两次评分，输出：

- **有效输出准确率、查准率、查全率和 F1**：只看成功得到入选决定的非 `either` 样本，用来判断模型答出来以后有多准；
- **覆盖率**：成功得到入选决定的样本占全部非 `either` 金标样本的比例；**完整准确率**则用全部非 `either` 金标样本作分母，把模型失败或回答不合格式也算作没有正确完成；
- `either` 始终不进入上述质量指标的分母；报告另外记录决定样本失败数与 `either` 失败数。`goldSelectRate` 按全部非 `either` 金标计算，因此同一批样本在不同模型间应保持一致；
- 门槛从 40 到 90 每隔 2 分（范围可以在下面说的 `DEPLOYMENT.selectionGold` 里改），各自会得到什么结果；门槛扫描同样同时报告有效输出准确率、覆盖率和完整准确率；
- 判错的条目，完整报告写到 `.data/eval/`。

不传 `--models` 时，评测用“精选评分”这一步线上正在用的模型：后台“模型与评测”页切换过的优先，其次是环境变量 `SCORE_MODEL`，再其次是 `site/models.ts` 的 `DEFAULTS.score`，都没有就用默认模型（`.env` 里的 `LLM_*`）。`--models default,deepseek-flash` 可以在同一批样本上比较几个模型。其他常用参数：`--n 200` 最多抽多少条，`--split holdout` 只跑留出集。在 `site/site.ts` 的 `DEPLOYMENT.selectionGold` 里写好样本文件、抽样条数、只抽哪一份和门槛扫描范围，以后不带参数运行就用这一套。

同一次评测里，不同样本渲染出完全相同的评分输入时，只共享模型的评分结果，各样本仍按自己的预筛结果、信源分级门槛和标注独立计分；失败的结果也在这次运行里共享，这样第一次跑和用已有结果重跑覆盖的样本一样。重复运行会复用已有回执。报告里的 token 用量和平均耗时，按相关回执的全部请求尝试汇总，解析失败后的重试也算在内；用已有结果重跑时，显示的是这些回执累计的用量，不代表这次新增的费用。

### 3. 看错例，改标准，再跑

在 `.data/eval/` 的报告里逐条看判错的资料：

- 该选没选上，多半是评分标准里没说清它为什么重要：在 `selection-score.md` 引用的共同规则 `selection-score-rules.md` 里，把这类价值写进“必须正常评价”的部分，给出例子；chat 和 SystemOne 一起生效。
- 不该选却选上了，多半是噪声没压住：在同一份共同规则里写进“必须压住”的部分。
- 整体偏松或偏紧，而判错的条目分数都贴着门槛，再调 `industry/selection.ts` 的门槛。

先改标准，再动门槛：门槛只能整体移动，解决不了“哪一类判错了”。比较模型时不要只看有效输出 F1：如果覆盖率明显不同，还要一起看完整准确率；高分但经常无法完成结构化判断的模型，不应被失败样本从分母里“隐藏”掉。

## 换模型

后台“模型与评测”页能看到每一步当前用哪个模型、近期的成功率、耗时和 token 用量，也能直接切换（只影响之后的新任务）。换评分模型之前，先用 `--models` 在同一批样本上比一比。

### SystemOne 决策评分

`decision-model-preview` 通过 SystemOne 协议返回候选决策，不是生成式聊天模型。它只用于预筛与评分；在 `.env` 设置 `PREFILTER_MODEL=decision-model-preview`、`SCORE_MODEL=decision-model-preview`，或在后台分别切换这两个步骤。不能填到 `LLM_MODEL`，也不能用于标题摘要、结构化、归组、综述或翻译；这些步骤继续用原有生成式模型。`site/models.ts` 的 `DEFAULTS` 保持空，未主动选择时不改变部署行为。

接入使用独立的 `SYSTEMONE_BASE_URL` 与 `SYSTEMONE_API_KEY`，北京基础地址为 `https://<WorkspaceId>.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`，实际请求端点在后面加 `/systemone`。新加坡工作空间用 `https://<WorkspaceId>.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1`，地域、工作空间和 key 要一致。不要为这个预设借用 `DASHSCOPE_API_KEY`：单独配置 `SYSTEMONE_API_KEY` 不会触发归组自动使用付费 embeddings。完整配置见 [改站指南](customize.md#systemone-决策模型可选) 和 `.env.example`。

评分共用 `selection-score.md` 引用的 `selection-score-rules.md` 中的**内容类型、五轴评价和各类型权重**，并保留材料不足时的分数封顶、噪声压制与安全边界，不把结果简化成“是否入选”二选一。一次评分包含这些决策项；两次评分各自发出一次实际请求，不将一次评分结果复制成两次。两次之和、页面平均分与 `industry/selection.ts` 的现有门槛规则不变；不能凭模型名称或协议直接改权重、门槛。

SystemOne 不返回生成式解释，预筛的 `reason` 留空，评分仍只产生整数分数；这不是“没有理由所以通过”，也不由其他模型补造评分理由。原始 `answers`（含 choice 与概率）及 `usage` 保存在回执中，运维可按后台内容诊断显示的回执编号核查，同时检查输出覆盖率与失败数。标题摘要和读者看到的推荐理由仍由写作步骤产生。

先由使用者填好有效 key、确认后台 `dashscope` 预算，再做同批对比，例如：

```bash
node --env-file=.env scripts/eval-selection.ts --gold .data/gold.jsonl --models default,decision-model-preview --split development
```

这是付费请求路径的一次真实评测，不承诺免费或更准确；填写配置前并没有完成实测。与现有模型比较有效输出质量、覆盖率、完整准确率、耗时与回执用量，再决定是否切换；若要调权重或门槛，仍按前面的金标校准流程来。
