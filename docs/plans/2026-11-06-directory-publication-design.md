# 360 专题目录直接公开

> 使用者已确认：360 AI · 专题推荐的历史与后续资料全部按目录公开，不再受模型预筛、相关性、拦截标签或写作材料长度限制。其他来源不扩展。
> 实施采用 TDD，先观察行为测试失败，再实现；不创建提交或分支。

**Goal:** `catalog-360-topics` 的新旧目录条目公开标题、已有简介和原文链接，无需购买模型分析。

**Architecture:** 来源及默认类别配置留在 `industry/selection.ts`。统一发布层按目录策略投影，保留人工可见范围、全文版权和来源参与模式；内容入口直接完成目录发布，不进入提取、分析和事件归组。历史模型分析与回执不改、不冒充模型 PASS，目录不自动进入精选。

**Tech Stack:** Node.js 24、TypeScript、PostgreSQL、pg-boss、node:test。

## 已确认的方案

仅预筛 PASS 已实际证明不能满足需求：四条 writer none，另一条含“其他”标签。扩大模型范围仍不能保证每条公开，并继续花费模型额度。选择目录直接公开：采用源站标题和简介，默认归“AI 工具”，不使用历史模型评分或精选推荐。人工下架继续生效，无简介的专题仍可读名称与链接。原文全文只按既有授权规则展示，模型审核不代表转载授权。

## 实施计划

1. 在 `tests/publication.test.ts` 验证旧 UNKNOWN／BLOCK／writer none、无分析、短简介都从公开 API、全部 RSS、Agent 搜索与 Markdown 同步可读；人工下架与全文许可仍有效，其他来源不放行。
2. 在 `modules/source-catalogs/tests/collect.test.ts` 验证未来采集和修订立即公开，无模型回执或处理／归组任务；重复采集保留时间，人工下架不恢复。执行独立测试库的上述测试，确认目录场景失败。
3. 配置目录来源与默认类别，修改统一投影与内容任务入口；旧分析任务也直接完成目录发布，旧正文任务不再抓取正文。事务完成处理状态与公开投影，保留资料、分析、回执、人工修正和时间。
4. 添加 `scripts/publish-directory-sources.ts`，默认预览，`--apply` 才执行；逐条锁定、重建并审计，重复执行不重复记录。同步选择、信源和部署文档，明确该来源不再经过六源预筛流程。
5. 运行类型检查、定向／全量后端测试、独立测试、web 构建与现有 web 测试。备份运营数据库，再应用历史修复，恢复服务并执行 smoke；确认真实历史条目与公开出口数量。既有计时及缺少 WebKit 的问题单独记录，不改变依赖或放宽测试。
