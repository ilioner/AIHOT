# 采集元数据与内部分析

使用者已确认：不能把未经分析的内容笼统显示为“已下架”；采集应保留源站存在的封面、原标题、分类和链接。

## 设计

- `isolated` 只限制公开出口，不再跳过内部分析。`hot_signal` 维持仅热度处理。模型请求继续经过原队列、回执与预算，内部内容不参与公开精选、归组或推送。
- 不修改公开可见性的数据库枚举，后台根据参与方式、处理状态、有效判断和人工设置说明原因，区分内部参考、规则拦截、待分析、失败和人工下架。
- 利用现有 `articles.raw` 保存结构化 `sourceMetadata`，包括列表标题、原文标题、原始类别和标签、封面、列表/条目/原文链接。图片复用 `media`，不增加平行图片系统。模型分类与原始分类保持独立。
- 同一来源重抓补齐元数据和展示图片，不修改首次发现时间、稳定身份或仅因此购买重新分析；跨来源发现不覆盖原始来源字段。
- 六个目录源按真实响应字段适配；RSS 分类与封面、公众号封面、网页卡片的现有字段也接入同一存储链路。缺失字段不推测。

## 实施与验收顺序

1. 修改分析路由并增加隔离来源的本地模型测试，验证不泄漏到公开出口。
2. 补齐解析、幂等存储、后台原始信息及状态原因，增加既有测试文件中的行为用例。
3. 跑类型、后端、网页、构建及 smoke；浏览器核对后台。
4. 对六源做独立真实采集核验，补齐已有资料并补分析原先跳过的教程。保持安全阀、全文权限和 `#其他 → block`。

不执行 Git 提交，不删除历史数据。尚未获授权的内容即使分析通过也不自动公开。
