# SkillHub 漏推修复与定向补推

目标：修复已经复现的待推计数覆盖、专题地址身份丢失和英文重复响应识别错误，补推现有范围内遗漏的内容。

用户已确认修复后推送。保持 `publishedTools()` 的分类范围和自动推送开关不变，不将被排除的新闻、教程或其他栏目自动纳入；不重推全部 `exists`，不覆盖无关远端条目，不提交 Git。

## 实施顺序

1. 在 `modules/skillhub-push/tests/routes.test.ts` 增加从未推送条目的计数和列表测试，在 `tests/mapping.test.ts` 增加保留源条目身份的专题映射测试，在 `tests/push.test.ts` 增加英文重复响应与真实专题地址的本地假服务测试。先运行确认失败。
2. 修复 `api/routes.ts` 的统计合并顺序；`backend/push.ts` 的列表包含无推送记录的候选，读取不新增状态；读取文章已有的 `identity_key`，让 `backend/mapping.ts` 复用源条目已经确定的 fragment 身份，普通锚点仍去除；`backend/client.ts` 识别已知英文重复提示，不把普通 400 当成功。
3. 运行模块测试、类型检查、后端全量测试、前端构建与测试、站点冒烟；检查本地后台的待推列表和按钮。
4. 备份四个受影响专题的本地状态和远端 916 的完整数据到 `.data/`。校验远端当前内容后，仅修正 916 的 `canonicalUrl` / `slug`，回查确认远端保留专题身份；不借此覆盖名称、分类等其他字段。
5. 保留原推送记录，远端回查确认缺失后才对专题定向重试；通过现有 worker 队列补齐原规则下从未推送的候选，模型仍走原回执与预算。逐条 GET 核对新增记录的 ID、URL、canonicalUrl、slug；保留审计和结果。

## 验收

- 新候选不再被显示为待推 0，后台列表展示它且读取不改变推送状态。
- 四个不同专题保持四个不同的标准地址与 slug，普通网页锚点不会制造重复条目。
- 中文与已知英文重复响应都正确识别，其他参数错误仍可见。
- 本地待推归零，受影响专题各有经远端回查的正确记录；未授权的栏目不发送。
- 若登录失效、远端不保留 fragment 或存在冲突，停止相关写入并保留证据，不随机换 slug 绕过去重。
