
【标题自洽规则 — 让读者不点开就知道"这是关于谁的什么事"】

1. 标题必须点出核心主体：机构名 / 院校名 / 文件名 / 项目名 / 产品名。
2. 原标题已经清楚点出主体的：英文标题翻译成中文、中文标题保持原意，不要为改写而改写。
3. 原标题只是日期 / 代号 / 没信息量的 teaser（如 "2026-10-29"、"重要通知"、"重磅发布"）时，结合【来源】和正文把主体补进标题。例：原标题 "重要通知" + 来源 "教育部职业教育与成人教育司" → "教育部职成司发布专业教学标准修订单"。
4. 补主体只能用【来源】或正文里真实出现的名字。正文和来源都没点出具体文件号或院校名时，用上位词（如"教育部一份关于产教融合的新文件"）兜底，绝不凭"行业常识"编一个具体文件号 / 院校 / 数字。
5. 原标题表达的【文章类型和核心动作】是硬边界：How / Why / Guide / Analysis / Review / Benchmark 这类解释、分析、教程或评测标题，中文标题必须保留这个类型；不能因为正文谈到一份已经存在的文件、政策或新数据，就改写成“印发 / 出台 / 发布 / 启动”。只有原标题明确宣布了印发、出台、发布或启动，中文标题才能使用对应动作。保留文章类型不等于删主体：仍须按第 1-4 条补全正文或来源明确给出的机构、文件、项目名。
   例：原标题 "How AI tutors reshape vocational training" → "AI 助教如何改变职业实训教学"，不能写成 "某公司发布 AI 助教"。
   例：原标题 "How to build interactive experiences with canvases" + 来源和正文明确是 GitHub Copilot → "GitHub Copilot 如何用 canvases 构建交互体验"，不能只写成缺主体的 "如何用 canvases 构建交互体验"。
6. 本条的动作和背景里的旧发布要分清：原文把发布写成过去的事（“At DevDay, we introduced …”“Last week we launched …”“上周我们发布了…”），本条是在讲用法、做演示或再次推广时，标题写介绍、演示或讲解，把发布交代成此前的事；不能写成“推出 / 发布 / 上线”，否则读者会当成今天的新闻。只有原文明确某项能力是现在才开放或新增，才对那一项用对应动作。
   例：正文 "At the conference, we presented how the new training base works … See more below" → "院校演示会上讲解新建实训基地的运行方式"，不能写成 "该院校在会上启动实训基地"。
