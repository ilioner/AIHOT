# 工具目录与情报信源

本站的六个特殊入口由 `source-catalogs` 模块采集，使用固定信源 ID、`external` 类型和空配置。地址、响应结构与身份规则集中在 `backend/adapters.ts`；不用虚构 RSS，也不要求目录具备原文发布日期。公开读取仍走统一发布层；360 推荐专题按目录直接发布，其他入口的预筛、评分、结构化、摘要、归组和预算仍走原框架。

## 入口与身份

- `catalog-aibase`：读取 AIbase 产品库公开 HTML 中的产品卡片，以详情页 URL 去重。接口已要求登录，不依赖该接口。源站对简化的 HTTP 请求返回 429/500；使用固定的普通浏览器 UA 和 HTML Accept 后实测返回 200，不轮换身份、不绕过验证码。若再受限则记录失败，等下一周期，不紧密重试。
- `catalog-aihot-tip`：读取公开 JSON 的 `tip` 类别，保留聚合页、原文 URL、原发来源和 attribution。按使用者确认的来源策略预筛直通 PASS，仍需完成后续分析，通过后公开摘要和原文链接；全文展示与全文分发默认关闭，模型判断不代表取得转载许可。
- `catalog-360-teacher` / `catalog-360-student`：读取专题 44 / 45 的全部工具，以 360 工具 ID 去重，同一工具出现在两个专题只新增一条资料，但保留两条发现记录。学生专题的真实范围是求职辅助。
- `catalog-360-topics`：每个推荐专题单独入库，保留 `#/subjectdetail?id=…`，不会全部合并成首页。按使用者确认直接公开目录：新旧条目展示源站标题、已有简介和链接，不经过模型预筛、评分、写作或自动归组，不自动进入精选。无简介也展示；人工下架与全文版权限制保留，默认归“AI 工具”。
- `catalog-uisdc`：读取最新一页的全部日包，再展开每包全部 `dubao` 子项，继承父包时间。有子项链接则使用该链接；没有则明确指向情报首页，不伪造独立文章地址。身份使用日包 ID 和链接或标题的哈希，不依赖数组顺序。无链接条目若改标题会视为新条目；源站没有提供更稳定的子项 ID。

360 的 `m` / `m2` / `uid` 是普通浏览器客户端在无账号状态下生成并持久化的匿名标识，不是登录凭据。模块使用固定匿名标识，不使用用户浏览器账号、不轮换标识。

## 时间、内容与分类

使用者确认的预筛直通来源是 `weblist-aixzd-tools`、`catalog-aihot-tip`、`catalog-aibase`、`catalog-360-topics`、`catalog-360-student`、`catalog-360-teacher`，由 `industry/selection.ts` 维护，不在采集器内伪造模型判断。这个名单与模块六个采集入口不同：星踪岛使用框架网页采集，优设不在直通名单。360 推荐专题后续改为目录直接公开，不再进入预筛队列；其他五个直通来源继续后续分析和发布检查，`#其他`、材料不足、失败和人工下架仍不公开。默认 UNKNOWN／BLOCK 拦截规则适用于未直通来源。旧模型分析与回执不修改，历史处理见 [部署更新](../../docs/deploy.md#更新)。

采集保留 `raw.sourceMetadata`：列表标题、原文标题、源站分类/标签、封面、条目/原文/列表链接；图片同时写入 `media`。360 保存分类层级，AIbase 保存卡片类别与图片，优设保存标签、图片和正文中明确的全文链接。教程 API 未提供图片时留空，不把站点 Logo 当成封面。补采元数据不改变首次发现时间或触发付费重分析。

除 `catalog-360-topics` 的直接目录策略外，目录资料经过正常预筛和分析，只有 `PASS` 继续，`UNKNOWN` 与 `BLOCK` 都不公开。已有完成分析的资料通过发布策略修复脚本重建，不重新购买分析；未分析或失败资料仍需在内容诊断中处理。360 推荐专题的直接策略优先于六源预筛直通策略，历史执行 `scripts/publish-directory-sources.ts --apply`，保留原分析与收费回执，不伪造模型 PASS。

目录没有发布时间时，保留 `published_at` / `publication_time` 为 null，通过 `MaterialInput.undatedPolicy = "discovery"` 明确选择首次发现时间线。存储层保存 `discovered_at` 与 `timeline_at`，原始元数据记 `timeBasis=first-observed`。重复读取、顺序变化及内容修订不会重写首次发现时间。详情页沿用现有“收录于 / 收录时间”标注，结构化数据不输出假的 `datePublished`。

普通信源不传该策略，仍按原规则将未知日期归档；显式回填、过期或未来的源站日期也不会因这项策略冒充今日新闻。优设的源站时间是日包时间，并非每个子项各自声明的独立发布时间。

新增 `ai-tools`（AI 工具）类别，承接工具目录、导航和专题推荐，与教程、能力发布、教学应用区分。正文与来源标签进入原有模型链路，逐条按当前运行时类别判断；不在采集器中伪造分析、评分或强行放行。`#其他` 仍为 block。所有来源保持摘要与链接模式，全文许可关闭。

## 调度与更新

模块接管这六个 ID 的后台“立即抓取”，每 15 分钟扫描到期来源；目录和教程每 24 小时、优设每 6 小时检查一次。队列不即时重试，失败也推进下一次时间，并写入 `fetch_runs`、错误、失败次数和健康状态。暂停来源不抓取；自动任务只有 `COLLECT_ENABLED=true` 才执行。手动脚本只抓指定六个来源，不开启环境安全阀。

首次站点初始化使用 `industry/sources.json`。已有站点用幂等脚本，只创建缺失来源、新增缺失类别，不覆盖管理员配置或删除历史：

```bash
node --env-file=.env modules/source-catalogs/scripts/sync.ts
node --env-file=.env modules/source-catalogs/scripts/sync.ts --apply
node --env-file=.env modules/source-catalogs/scripts/sync.ts --apply --collect
```

最后一条实际联网并提交处理队列；若站点已有启用模型的 worker，会继续按原预算处理。首次接入收集当前页面全部可见条目，不承诺穷尽平台历史。所有源的创建与手动采集有审计记录，无数据库迁移或删除操作。
