# 微信读书采集（公众号）

在后台扫码登录一个或多个微信读书账号，用这个账号池搜索公众号、把一个公众号加成一个 `mp_account` 信源，然后定时抓取它的文章。

这一版走微信读书的移动端接口：账号扫码授权 → 用 `MP_WXS_<uin>` 作为公众号标识 → 从微信读书的收藏/公众号列表读文章，从阅读器接口取正文。文章照常经过框架的 `upsertMaterial`，所以识别、时间线、正文清洗、筛选和归组都还是引擎的规则。模块不发版、不改引擎，只做公众号这一种信源。

## 用起来

1. 打开后台「公众号 → 微信读书采集」，点「生成二维码」，用手机微信扫描并确认。
2. 账号进入「账号池」后，在「添加公众号」里输入公众号名称，或粘贴一篇文章的链接后搜索。
3. 点「添加」：它成为 `mp_account` 类型的信源，`interval_minutes` 是 60（可在信源详情里改）。
4. 定时任务每 15 分钟看一次，按各信源的间隔入队抓取；「立即抓取」不需要等。

首次检查只看最近 7 天的文章（更早的是历史，不是新闻），每次最多入 8 篇；之后每次只补新的，正文取失败会按重试窗口再取几次。

## 避免限流 / 多账号

一个账号就能用，多扫几个更稳：请求会在账号之间轮换，被限流的账号自动退避，池子全忙时这一轮直接跳过。

- **请求之间隔一会儿。** 同一个账号两次请求之间至少隔 `WEREAD_REQUEST_INTERVAL_MS`（默认 2500 毫秒），并在这个基础上做 ±30% 的抖动，避免几个账号踩着同一个节拍打到平台。
- **每小时有预算。** 每个账号每滚动的 1 小时最多 `WEREAD_HOURLY_BUDGET` 次请求（默认 90）。窗口从该账号这一小时的第一次请求开始算，满一小时自动重开。
- **一个信源尽量待在一个账号上。** 每次抓取记住上次用的账号，它还可用就继续用它，这样不必反复激活另一个账号的会话；它正忙（还在间隔里、冷却中或预算用完）时才换池子里最快可用的那个。
- **被限流就退避。** 平台回 `-2014` 时该账号冷却 5 分钟，之后每连续失败一次翻倍，最多 1 小时；回 `-2041`（要人机验证）先试一次重新激活，仍失败则冷却 30 分钟起、翻倍到最多 6 小时，并在页面上写明原因。一次成功就把冷却等级清零。
- **同一个请求会换账号重试。** 只在「限流 / 要验证 / 登录失效」这三种情况下换下一个账号重试，最多试满池子里的账号数；网络错误和别的错误不换账号，免得每个账号都被敲一遍。换完后仍无账号可用，就报「账号池冷却中」。
- **池子全忙时这一轮跳过。** 所有账号都在冷却或预算用完时，这次检查直接跳过：`fetch_runs` 记为 `skipped`，信源的 `health` 和 `fail_count` 保持不变，只写一句说明，等下一个调度周期再试。
- **入队错开。** 定时调度给每个信源加 0–120 秒的随机延迟，免得同一批到期的信源在同一分钟挤在一起。
- **不绕过人机验证。** 遇到验证要求只会停下来冷却并在页面上写明原因，不会自动过验证码、换出口 IP 或做任何绕过。
- 后台「账号池」一栏显示整个池子的可用数量、本小时总请求数、下一个可用时间，以及每个账号的下次可用时间、本小时用量和冷却等级。

## 配置与风险

- 两个可选环境变量控制节奏：`WEREAD_REQUEST_INTERVAL_MS`（同一账号两次请求之间的基础间隔，默认 2500 毫秒，实际会在这个基础上 ±30% 抖动）和 `WEREAD_HOURLY_BUDGET`（每个账号每滚动的 1 小时最多多少次请求，默认 90）；不设就用默认值，测试里把间隔设成 0 以免等待。账号凭据（access token、refresh token、skey）用 `SESSION_SECRET` 派生的密钥做 AES-256-GCM 加密后存进 `weread_accounts`，后台接口不会返回明文。**轮换 `SESSION_SECRET` 后旧账号会显示「重新扫码」**，重新扫码即可。
- 扫码登录的是管理员自己的微信读书账号。微信读书可能限流或要求人机验证；遇到这两种情况模块只会停下来让账号冷却（规则见上一节），不会尝试绕过验证。
- 如果配置了 Dajiala（`DAJIALA_KEY`），引擎自己的公众号采集会接管这些信源，本模块的定时抓取会停，避免同一批文章被买两次。
- 模块只读公众号的公开文章，不改动账号里的任何内容。

## 数据

`weread_accounts`：一个微信读书登录一行（vid 唯一），`status` 为 `active`、`cooling`、`reauth`；`next_allowed_at` 是它下次可发请求的时间，`requests_hour` 和 `hour_started_at` 是滚动 1 小时窗口里已用的次数与窗口起点，`cooldown_level` 是连续失败的冷却等级（一次成功就清零）。删除账号只删这一行，已抓到的文章不受影响。
