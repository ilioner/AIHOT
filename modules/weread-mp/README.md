# 微信读书采集（公众号）

在后台扫码登录一个微信读书账号，用它搜索公众号、把一个公众号加成一个 `mp_account` 信源，然后定时抓取它的文章。

这一版走微信读书的移动端接口：账号扫码授权 → 用 `MP_WXS_<uin>` 作为公众号标识 → 从微信读书的收藏/公众号列表读文章，从阅读器接口取正文。文章照常经过框架的 `upsertMaterial`，所以识别、时间线、正文清洗、筛选和归组都还是引擎的规则。模块不发版、不改引擎，只做公众号这一种信源。

## 用起来

1. 打开后台「公众号 → 微信读书采集」，点「生成二维码」，用手机微信扫描并确认。
2. 账号进入「账号池」后，在「添加公众号」里输入公众号名称，或粘贴一篇文章的链接后搜索。
3. 点「添加」：它成为 `mp_account` 类型的信源，`interval_minutes` 是 60（可在信源详情里改）。
4. 定时任务每 15 分钟看一次，按各信源的间隔入队抓取；「立即抓取」不需要等。

首次检查只看最近 7 天的文章（更早的是历史，不是新闻），每次最多入 8 篇；之后每次只补新的，正文取失败会按重试窗口再取几次。

## 配置与风险

- 不需要新增环境变量。账号凭据（access token、refresh token、skey）用 `SESSION_SECRET` 派生的密钥做 AES-256-GCM 加密后存进 `weread_accounts`，后台接口不会返回明文。**轮换 `SESSION_SECRET` 后旧账号会显示「重新扫码」**，重新扫码即可。
- 扫码登录的是管理员自己的微信读书账号。微信读书可能限流或要求人机验证：模块遇到 `-2014` 会让账号冷却 5 分钟，遇到 `-2041` 先尝试重新激活、仍失败则冷却 30 分钟并在页面写明原因；它不会尝试绕过验证。
- 如果配置了 Dajiala（`DAJIALA_KEY`），引擎自己的公众号采集会接管这些信源，本模块的定时抓取会停，避免同一批文章被买两次。
- 模块只读公众号的公开文章，不改动账号里的任何内容。

## 数据

`weread_accounts`：一个微信读书登录一行（vid 唯一），`status` 为 `active`、`cooling`、`reauth`。删除账号只删这一行，已抓到的文章不受影响。
